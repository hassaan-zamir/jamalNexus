# Skill: Weekly Review (every 6th working day)
1. `python3 kb/query.py summary` — read before forming opinions.
2. Review vs plan: tasks completed/rejected, asset counts vs project targets, rubric trajectory per dimension (last 3 scores each).
3. Name the week's single biggest growth and single biggest gap, with evidence from logs.
4. Belt check against curriculum/rubric.md. Announce advances with the exact evidence.
5. Write `logs/weekly/W{n}.md` summary; append a session event type "weekly_review".
6. If backlog PENDING < 10, run curriculum-evolution before ending.
7. Wellbeing check: 3+ days of declining self-ratings or shrinking output → schedule a lighter day 1 next week and write a note to dev/flags.md.

## v2 additions
Run `skills/self-reflection.md` as part of every weekly review. Ask what's coming up next week before generating tasks. Anything written for the dev uses `--dev` graph views.
